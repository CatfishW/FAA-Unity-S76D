# Full XR-3 integration source profile

This folder preserves corrected source from the archived full integration project used for the installed Windows release. The repository's standard scene profile uses earlier canvas-based conformal components and does not import the optional spatial-workspace dependencies of this implementation. Unity ignores the `SourceProfiles~` directory.

`FaaRotorcraftConformalLayer.cs` is the exact implementation built for the deployed full integration profile. Its native mesh and world-text objects use the FAA HUD layer, and its camera callback admits the explicitly owned centered preview camera. These fixes preserve the terrain-free mixed-reality culling policy and the headset's calibrated stereo projection.

The shared imported `XR3DesktopHudPreview` retains the headset's far clipping range so its distant angular cue shell is visible. Full integration rendering regression tests run against the archived integration project; the standard-profile test suite explicitly skips the two optional full-profile tests. The native attitude window is projected from the physical HUD canvas to keep pitch rungs clear of fixed instrument lanes.

`FaaPilotChrome.cs` preserves the full-profile menu hit-test correction: desktop inside/outside clicks use the centered preview pointer camera, while the world canvas retains its headset camera.

The native aircraft camera now uses the shared `AircraftNativeXrOrigin` helper: an aircraft-driven parent carries flight attitude/translation while TrackedPoseDriver retains the head's local pose and stereo projections. Initial tracked position and yaw define the seated neutral pose; RECENTER SEAT recalibrates it. The full-profile camera, workspace, tracked-seat reference, conformal diagnostics, gesture input, and gesture lifecycle regression are preserved here as exact source snapshots. Shared origin regressions live in the imported AircraftControl Editor test assembly. Repeated focus-loss cancellation keeps a held pinch blocked until a real release.

An idle, untracked, or provider-reported absent headset uses a provisional aircraft-relative origin without claiming seat calibration. The first valid tracked HMD sample calibrates once only when user presence is also true if the provider exposes that feature; providers without presence retain the tracked fallback. Temporary absence or tracking loss preserves established calibration. Manual native RECENTER uses the same gate and refuses known absence without changing the prior seat; Settings explains: “Seat unchanged: wear a tracked headset to recenter.” `NativeXrSeatCalibrated` exposes this distinction, and a calibration version refreshes the stable cockpit-seat reference when provisional calibration becomes physical calibration.

The shared centered desktop view uses a normal enabled mono spectator camera (`stereoTargetEye=None`, display 0, no render texture) for both rendering and mouse hit testing. MR presentation excludes this owned camera from auxiliary-camera suppression. The former manual camera render and full-screen IMGUI texture overlay have been removed; headset pose and calibrated stereo projection matrices remain owned by XR.

Native workspace gestures prefer the active provider owned/reported by `XR3HandTracking`; native mode excludes desktop-offset Leap providers and consumes the same fresh hand status. Controller input and ordinary desktop-provider selection retain their fallbacks. A wall-clock device/frame watchdog recreates only the stalled provider's SDK controller after five unhealthy seconds, at most once per five seconds; a connected service pipe without a device is unhealthy, while fresh empty-hand frames are healthy. Disabled providers are not reset.

`XPlaneDiscoveryWeb.cs` preserves the exact corrected full-profile native Web API discovery implementation from `Assets/_Project/Scripts/XPlaneIntegration/Runtime/XPlaneDiscoveryWeb.cs` in the integration build stage. The standard imported profile lacks the full source-discovery/configuration dependencies, so this snapshot remains outside Unity import; do not copy it into `Assets` by itself. Its original script metadata is preserved beside it.

`IndicatorControlsPanel.cs` and `IndicatorSystemController.cs` preserve the exact full-profile chrome integration for the reference traffic symbols, KEY / STYLE flyout, projected HUD bounds and immediate MR layer propagation.
