# Switchable non-conformal symbology: Digital and Classic Analog

## In-game use

Open the existing side-mounted **Settings** panel with **SETTINGS / F9**, then use **LOOK RIGHT** to inspect it on a laptop (look toward it in XR). Select the **SYMBOLOGY** tab and choose **DIGITAL** or **CLASSIC ANALOG**. Switching is explicit and works while gesture editing remains locked; no camera is started. Return to flight view with **FORWARD / R**.

The **INSTRUMENTS** tab controls the currently selected version's instruments. Its per-instrument slider, +/- buttons, presets and group-size controls also work on the new analog dials. Existing webcam multi-finger group sizing and tracked-hand size adjustments operate on the active version. Switching cancels a gesture in progress, preventing it from applying an old baseline to a different version.

During an explicit desktop **LOOK LEFT/RIGHT** panel inspection, Classic follows the same intensity policy as Digital. Essential awareness readouts (the airspeed, altitude, torque and NR windows with their values and units, the VS readout, the mode row, the heading fallback and the data flags) stay at `max(FaaSpatialWorkspace.ForwardIntensityFor(t), FaaHudInspection.AwarenessHudIntensity)`, which is 0.65 while inspecting. Everything else (dial rings, ticks, numerals, needles, the attitude ball, roll scale, LOC/G/S and the VSI scale) uses `ForwardIntensityFor(t)` (0.16 while inspecting; 1 for the instrument being resized from Settings). The dimming is applied to element colours, so the Classic root `CanvasGroup` carries only visibility and the legacy `PanelInspectionOpacity` multiplier (the workspace leaves it at 1). Optional hooks: `AwarenessFloor` (a fixed floor in place of the shared one), `PreviewInstrumentId` (one more instrument held at full intensity) and `DeclutterDeviation` (an external LOC/G/S declutter). `ForwardIntensity` and `AwarenessIntensity` report what is applied. Layout, data updates and canvas projection do not move or switch. **FORWARD / R** restores full intensity. Native XR continues using its normal canvas depth/order rather than this desktop inspection behavior.

Each version keeps its own instrument sizes. The existing Digital workspace profile remains compatible. The selected version, Classic sizes and presentation choices are saved separately under the existing scene/device key plus `.Symbology.v1`. Radar/utility panel coordinates remain in the original profile and never change when selecting a style. Invalid/unsupported preference documents fall back to Digital. The developer F8 renderer toggle is separate; an explicit style choice returns to the uGUI flight renderer so the chosen style is visible.

## Reference design and deliberate interpretation

Classic Analog is built from native scalable Unity UI geometry and TMP text, not a static screenshot stretched over the view. The user's supplied reference is the visual basis for the lime-green palette, large circular speed and altitude instruments, smaller torque/RPM instruments, upper bank arc, central solid/dashed pitch bars, four-dot course-deviation layout, and right-hand vertical indications. Its black background is treated as transparency so the cockpit/outside scene remains visible.

The photograph is not an interface-control specification. Its sample values (140 knots, 1400 feet and 78%) are never hardcoded into the live view. Some dial markings and C/R/P mode mappings are ambiguous in the image. The following mappings are explicit implementation choices, rather than claims about an aircraft-certified instrument:

| Element | Current source and mapping |
|---|---|
| Airspeed | Actual indicated-airspeed dataref, 0–240 knots around one clockwise revolution, window unit **KT** below the value. Values above the scale peg the needle and show OFF SCALE with the true value; they do not wrap back to zero. A red radial marks VNE (155 kt, demonstrator value). |
| Altitude | Actual MSL altitude. One needle revolution is **1,000 feet**, dial labels 0–9 are hundreds of feet, and the window shows full feet MSL with a thousands separator (`8,182`, unit **FT**), so the cyclic pointer is never ambiguous. There is no separate thousands text. |
| Torque | Maximum of the available expected engines, 0–120% dial (same scale maximum as Digital), window unit **TQ %**. The per-engine values `L nn   R nn` appear beneath it only when they add information: a split of 5 points or more, or one expected engine lost (the combined maximum is then flagged invalid). |
| RPM | Actual primary **rotor** NR percentage, 0–120% dial, window unit **NR %**. Engine N2 is not silently substituted. |
| Bank/slip | Actual roll and side-force/slip telemetry. Invalid channels remove their moving pointer. |
| Vertical speed | Actual feet/minute, +/-2,000 fpm instrument range with an off-scale indication and numeric value outside that range. Same caption and format as Digital: **VS FPM** above the scale, signed readout below it at 50 FPM resolution with a true minus sign and unsigned zero (`+1350`, `−650`, `0`; `FaaEngineInstrumentGraphic.FormatVerticalSpeed`). |
| LOC / G/S | Existing navigation-valid state and a real deviation dataref. The scales are drawn only while guidance is expected (valid signal, or NAV / G/S engaged or armed); otherwise nothing is drawn. Expected but lost guidance shows a boxed amber `LOC` / `G/S` flag and no diamond. A pegged diamond is drawn hollow. A map target is not substituted for an ILS signal. |
| C/R/P and status | `FaaFlightModeAnnunciation.Compose` over read-only X-Plane active/armed mode bits and the flight-director/autopilot mode, shared with Digital. Fixed columns C \| R \| P \| STATUS in the top-centre mode row, with the Digital geometry and format: bold 28-unit active modes, a small quiet axis prefix (`R:`, `P:` from `FaaClassicAnalogHud.FmaPrefixes`, which the Digital row also reads) right-aligned just outside the change box, 20-unit armed modes below. The change box fits the mode text. The C column stays hidden until a collective-mode source exists. With AP/FD off no modes are shown. Armed modes (cyan, second row) appear only when distinct from the active mode. A changed active mode is boxed for 10 s; an AP/FD disengagement shows a boxed amber **AP OFF** that flashes for 5 s, stays steady to 10 s, then clears. A stale feed shows `FMA --`. No flight-control commands are sent. |

AP-mode references: https://developer.x-plane.com/article/accessing-the-x-plane-autopilot-from-datarefs/ and https://developer.x-plane.com/article/flight-director-and-autothrottle-datarefs/ . These source meanings are separate from the user's visual reference.

Limit marks and exceedance coding come from `FaaRotorcraftLimits` (shared with Digital). These are **demonstrator values, not S-76D RFM data**: TQ caution above 100 %, warning above 110 %; NR warning below 91 % / above 110 %, caution below 95 % / above 107 % (low side only when airborne); VNE 155 kt. Dials carry a red radial at each warning limit and an amber arc over each caution band. In a caution band the needle, value and window turn amber; beyond a red line they turn red. Either state adds a second (inner) window box and flashes the value at 2 Hz for 5 s, then holds steady. A small hysteresis keeps a value that rides a limit from restarting the flash.

Failure flags are the most conspicuous element at the data they replace (they keep the awareness intensity while a panel is inspected): an invalid channel removes the needle and numerals and puts a boxed amber mnemonic (`IAS`, `ALT`, `TQ`, `NR`, `ATT`, `HDG`, `LOC`, `G/S`) in its window. When the whole feed is stale, one boxed **NO FLIGHT DATA** flag at the attitude centre replaces the per-instrument flags (the VSI keeps its documented `NO DATA`).

## Screen layout (Classic)

Classic follows the shared screen-zone plan. The mode row sits in the top-centre FMA zone (y 16–80 reference units, the same row as Digital). The attitude inset is at the screen centre, with the roll scale concentric with it. Airspeed (left) and altitude (right) have their centres on the attitude reference, symmetrically placed. Torque and rotor-NR dials sit below them, moved outboard only as far as needed to keep the shared heading-scale slot (zone Z5, about x 700–1220, y 790–850) free. The heading tape is the heading reference in both styles. A fallback `HDG nnn°` readout appears in that slot only while the tape is hidden. The G/S scale sits between the attitude and the altimeter, the LOC scale just above the heading slot, and the VSI right of the altimeter. Nothing is drawn below y 990 or in the top corners. Classic publishes the clear attitude field as an `AttitudeWindow` keep-out region (`TryGetAttitudeWindowScreenRect` / `TryGetAttitudeClearZone`): between the dials, above LOC or the heading slot, and with its top 85 units (times the roll-scale size) above the attitude centre, below the roll-scale end marks, so the scene-cue ladder never reaches them. The roll scale also publishes small Symbology keep-outs around each end mark, the fixed top index and the moving sky pointer (`classic-roll-end-left/right`, `classic-roll-index`, `classic-roll-pointer`), so the conformal horizon gaps around them instead of striking through the arc. The dials, VSI and mode row are already published as symbology keep-outs by the workspace.

Roll scale: one convention for both styles. The filled **sky pointer** moves with the sky (counter-clockwise for a right bank) at 1:1 against fixed indices at 10, 20, 30, 45 and 60 deg. A hollow fixed index sits at the top, and the slip brick sits under the moving pointer. Beyond 60 deg the pointer is drawn hollow.

Unusual attitude: with hysteresis (engage above 60 deg bank, +30 deg or −20 deg pitch; release below 55 deg and inside −15/+25 deg), Classic hides the LOC/G/S scales, the torque split caption and the armed modes. Red recovery chevrons pointing toward the horizon appear when the horizon is off the inset.

## Attitude vs conformal scene geometry

The subsequent [reference VSI revision](REFERENCE_VSI.md) places `1`/`2` numerals inside the scale, adds rounded shoulders to the zero notch, and moves a detached rounded pointer outside the numeric column. The live range, signed readout, invalid-state behavior and existing animation remain unchanged. Recent source discovery and release status are described in the current README; the measured results below describe the original analog implementation pass.

The Classic center offers **ATTITUDE INSTRUMENT** or **CONFORMAL SCENE CUES**. The former is a head-fixed attitude ball (radius 135 units, inside the roll scale) with a moving local pitch/roll ladder, explicitly **non-conformal** and drawn so it reads as an instrument, never as a second outside horizon (AC 25-11B: a non-conformal horizon looks distinctly different from a conformal one; sky and ground clearly separated):

- a translucent sky (blue, alpha 0.22) and ground (brown, alpha 0.42) fill clipped to the ball, behind the strokes, so the outside view stays visible;
- the same gull-wing **W** aircraft reference as Digital (72 x 12 units, the Digital 6:1 shape), fixed at the ball centre, which sits on the screen boresight;
- a horizon across the whole ball (about 270 units wide in level flight), heavier than every rung and gapped for the W, without a label;
- labelled rungs only every 10 deg, labels at both rung ends and upright relative to the rung, positive rungs solid and negative rungs dashed, ends turned toward the horizon; 5-deg marks are short and unlabelled; there are no 2.5-deg minors. A rung whose label cannot be placed inside the ball is not drawn at all (never a rung without its numeral), so typically two or three labelled rungs are visible;
- when the true horizon is within 12 units of the ball edge (about 23 deg of pitch) it is held there and dashed, keeping a sliver of sky and ground visible; red recovery chevrons appear in unusual attitude.

Scale: 5.4 units per degree, so the ball edge is 25 deg from the aircraft symbol (AC 23.1311-1C: at least +25/−15 deg visible, at most 50 deg in total). **Trade-off:** the inset horizon cannot also be registered with the outside horizon. At the 60 deg camera field of view the outside world moves about 16 units per degree, so a registered inset of this size would show only about ±8 deg and would lose its horizon in normal manoeuvres. The ball is therefore caged and non-conformal: its aircraft reference sits on the boresight, so in level flight the inset horizon and the outside horizon coincide, and away from level flight the instrument styling (fill, round ball, W) keeps the two from being confused. The registered (conformal) horizon is the **CONFORMAL SCENE CUES** centre. In inset mode the scene horizon/boresight are suppressed, and the conformal FPV and selected FPA must not be drawn over the inset either (two pitch scales in one place invite misreads; that gating lives in the conformal layer). Selecting the scene-cue center hides the local attitude inset and restores the scene-aligned attitude rendering, confined to Classic's published attitude window.

No version switch changes camera FOV, IPD, native lens distortion, flight telemetry or radar positions. Existing whole-HUD and individual instrument visibility controls are respected. The previous removed green control strip stays removed. Settings/Hand Studio remain in protected side positions, with right-button and XR grip dragging unchanged.

## Animation and responsive layout

New gauges use a frame-time-based exponential response rather than frame-count-based lerp. Roll and heading use shortest-angle interpolation. Altitude is smoothed as a continuous value before converting to a cyclic needle angle, avoiding the 359-to-0 reverse spin. First valid data, recovery after stale data and large discontinuities snap to the trustworthy sample rather than slowly sweeping from an invented zero. Invalid channels suppress their live pointers immediately. **MOTION: DIRECT / REDUCED** removes extra presentation smoothing; **SMOOTH NEEDLES** restores it.

Dark outlines on the native vector strokes, a TMP underlay halo on every glyph (`FaaHudStyle.ApplyHalo`, strength 0.9) and translucent dark dial faces (alpha 0.30) and window plates (alpha 0.50) give at least 3:1 local contrast over haze and terrain without an opaque panel behind the flight display (the fills never carry the stroke outline). Text follows the `FaaHudStyle` floors: dial numerals, units, captions, the VSI numerals and pitch labels at least 18, window values and the VS readout at least 24, axis prefixes 16, nothing below 15 reference units; units and captions are drawn at full alpha. The floor is enforced at the rendered size: when a module is shrunk (or the composition is fitted smaller), its text grows so that it never renders below 15 reference units, and returns to nominal when the module is restored. Dial numerals stay upright. The needle is clipped out of the digital window. On the big dials the needle also leaves the numeral band empty: the shaft ends at radius 62 and the pointer tip starts at radius 103 over the ticks, so the needle never covers the numeral it points at (the small dials carry their numerals outside the ring). The windows are tall enough that the value and the unit below it never share a TMP line box (airspeed/altitude windows 55 units high with value and unit centres at −23.5/−49.5, torque/NR windows 57 high at −21.5/−47.5), and both stay clear of the exceedance inner box. Text is assigned only when its content changes, and meshes rebuild only when their inputs change (during the 0.2 s inspection fade the colours change every frame).

Individual scaling separates adjacent dials. Group scaling expands their composition together, with an outer fit limit that keeps instruments inside the current viewport rather than clipping them at extreme sizes. Local coordinates are used for this layout; it is not recomputed from a moving head/world camera. The default Classic green keeps the supplied reference hue (94 deg) at higher luminance (`FaaClassicAnalogHud.DefaultReferenceGreen`, 150/235/90, relative luminance about 0.67 instead of 0.40) for contrast over terrain and haze. **COLOR: PILOT PALETTE** follows the existing pilot-selected color instead.

## Implementation boundaries

`FaaSpatialWorkspace.Symbology.cs` owns style selection, visibility gates, module bindings and independent preferences. `FaaClassicAnalogHud` owns the reusable Classic view; `FaaClassicGaugeGraphic`, `FaaClassicAttitudeGraphic`, `FaaClassicBankGraphic`, `FaaClassicDeviationGraphic` and `FaaClassicBoxGraphic` (mode-change and flag boxes) draw native vector geometry. `FaaClassicClock` is the single flash/box clock. `FaaAnalogFlightSample` is a read-only adapter over the existing bridge; `FaaAnalogAnimation` supplies presentation filtering. The view is built once, and switching reuses it instead of creating duplicate canvases or telemetry workers.

To add another style, define its instrument roots/captions and renderer, register its separate module set and persisted size list, and extend the explicit style enum/selector. Never reuse the conformal layer as a scalable screen instrument and never copy a screenshot's example data into live telemetry.

## Validation

`RunAnalogAssertions.cs` runs focused NUnit fixtures with setup/teardown. `FaaClassicLayoutTests` covers zones, pairwise text overlap (TMP line boxes) in normal, failed, stale, AP OFF and off-scale states, text floors, alpha and halo, the rendered-size floor for shrunk modules, upright numerals, needle/window clearance, the empty numeral band on the big dials, the sky-pointer sign and tick set, FMA format (Digital prefixes, bold modes) and blanking/boxing/AP OFF timing, deviation declutter, limit coding and hysteresis, flags, unusual-attitude declutter, the attitude ball (pitch range, 10-deg labels inside the ball, W, sky/ground fill, off-scale horizon), the awareness/forward intensity split while inspecting, and the roll-scale keep-outs and window top. `FaaReferenceVsiTests` checks that the VS caption and readout match Digital. `RunAnalogRuntime.cs` checks in-game style switching, independent sizes, declutter, stale/invalid signals and preservation of radar/conformal state. `verify_symbology_mouse.py` drives the actual active UI input module with a temporary Input System mouse. `verify_analog_frames.py` records settled UI geometry over 300 rendered frames while switching versions, opening the side panel and changing size.

Reports and previews are in `artifacts/analog-symbology/` and `Assets/artifacts/analog-symbology/`. Synthetic values are confined to isolated test fixtures, never the live simulator bridge. Final measured results belong in the generated verification report. Physical XR-3 optical behavior, pilot workload, native-device performance and a complete player build are not established by these Editor checks. This is research-simulator software, not FAA-certified flight equipment.

### Measured local results

The figures below predate the October 2026 human-factors revision (layout zones, sky pointer, FMA, limit coding, flags, declutter) and must be re-measured for it.

Final compilation on Unity 6000.5.10f1 reported zero script errors. The direct Editor runner passed 353 cases (35 new analog cases plus existing regressions); Play-mode runs passed 29 analog integration checks, 24 radar/Brief/drag checks and 27 conformal-HUD checks: **433 focused checks total**. These are direct assertion runs, not a full-project Unity Test Runner XML report.

Two actual Input System mouse clicks, processed by the active XRUIInputModule on the side Settings panel, switched Digital to Classic Analog and back while gestures remained locked. A 300-frame render probe collected 200 settled samples across five style/size/inspection phases. The four checked gauge groups had zero measured rectangle movement within each settled phase; 160 Classic samples had fresh flight data while altitude changed. This verifies layout stability, not a promise of a particular hardware frame rate.

Classic Analog is selected and saved for immediate inspection. The camera was never opened for testing, no simulator commands were issued, and no player package, commit or push was produced. The existing unsaved scene remains preserved. Machine-readable evidence: `artifacts/analog-symbology/analog-symbology-verification.json`.
